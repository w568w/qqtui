# 验证范围与复现入口

宿主测试环境为 Linux x86_64、QQ 3.2.34-53644、Kitty。兼容配置见 bridge/compatibility.json。

| 层次 | 验证范围 | 入口 |
|---|---|---|
| 状态与存储 | 事件缺口、作用域、历史分页、引用、撤回墓碑、版本化草稿、账号交接、发送确认单调性、SQLite WAL | cargo test --locked |
| 本地传输 | 并发响应关联、取消清理、半帧断线、连接生命周期、帧限制 | Rust backend 测试 |
| 桥接与日志 | 原生参数、发送去重、NOSEQ、会话变化、回执迁移、角色权限、媒体准备、通知判定 | node --test tests/native.test.cjs tests/journal.test.cjs |
| loader | 限定 manifest 的只读重定向、原始写路径、无关文件不重定向 | python3 tests/loader.test.py |
| 真终端 | 历史锚点、双向分页、鼠标、头像、图片裁剪、动图、预览、转发选择、引用往返、禁言和解除、表情发送 | python3 tests/tui-history.test.py --binary target/debug/qqtui |
| 终端边界 | 不响应光标查询的伪终端、持续缩放、退出恢复、账号选择框 | terminal-resize.test.py、account-picker.test.py |
| 桌面通知 | 独立测试总线、正文转义、原生重要提醒、窗口标题、会话已读菜单 | desktop-notifications.test.py |
| 发行包 | 原生包文件与依赖元数据、系统 noVNC、软链接路径、私有桌面、并行宿主、VNC 重连、组件故障关停 | python3 tests/package.test.py <pkg.tar.zst> |

统一执行 `python3 scripts/check.py`；`--terminal` 加入完整终端组，`--package <pkg.tar.zst>` 加入包沙箱组。包沙箱依赖 bubblewrap 和已安装 QQ，可通过直接调用 package.test.py 的 `--qq-path` 指定 QQ 安装根目录。真终端测试另需 Kitty、Xvfb、xauth 和 Python Pillow；桌面通知测试另需 python-dbus、python-gobject 及系统 D-Bus 工具。

## 关键验收条件

- 仅有效请求作用域能更新当前视图；发送回执作为持久事实保存，确认不能降级；结果未知不自动重发。
- 发送暂存、账号交接和退出按已登记的数据库顺序落盘。保存失败保持可恢复数据；未加载或未修改的草稿不覆盖持久记录。
- `]q`／`[q` 双向回绕且排除群助手子树，搜索和原生重要提醒规则独立保留。
- 头像按 UID 关联，连续发言分组，未知资源占位，窄窗口收起；图片占位按实际几何计算，选择和资源到达不能改变阅读锚点。
- 合并转发选择独立于滚动，可访问非首条媒体和嵌套记录；关闭后恢复父级位置。
- 原生禁言及角色决定输入能力，发送前再次检查；权限状态包含未知值。操作失败提示到期清除，失败记录仍可恢复。
- 多个可见表情缓存补齐后不持续重复编码；窗口、解码、队列和热回执有预算。清理不删除受草稿、未决发送或活跃文件租约保护的资源。
- QQ、私有 D-Bus、Xvfb 的启动失败或意外退出进入统一清理，不影响另一个账号；查看器有认证、重连宽限和最大存活时间。

## 实机与平台边界

实机核对头像、联系人、历史、权限、会话顺序与未读。发送测试使用专用对端，在 QQ 历史中核对消息及回执，并在宿主重启后检查请求去重。已读测试核对本机操作对应的原生状态变化。

包沙箱使用临时 HOME、进程／IPC／网络命名空间和独立显示，挂载宿主机的 /usr 和 /etc。完整安装测试在干净 Arch 环境中构建和安装软件包，以普通用户运行 qqtui 完成首次登录。

Windows CI 检查前端与命名管道。

升级测试逐个恢复账号，核对草稿、发送记录及其他持久数据。
