# 架构

## 状态归属

启动选择器只负责选择宿主实例，每个 TUI 窗口固定一个账号。原宿主保持原路径；新增宿主按 QQ 号隔离配置、状态、socket、Xvfb、私有 D-Bus 和 systemd 服务。显示编号分配在用户内串行化，防止并发启动抢占同一显示。

QQ 的浏览器 userData/sessionData、原生引擎 desktopGlobalPath 和登录 commonPath 按实例管理；会话 desktopPathConfig.account_path 指向原始 QQ 数据根目录。初始化会话前校验预期 QQ 号并取得独占账号租约；退出释放自己持有的租约，宿主启动时清理已退出进程留下的租约。

完整 QQ 持有账号、设备信息、网络连接、消息同步和原生数据库。会话顺序、置顶、未读数由 RecentContactService 提供；消息操作调用 MsgService。好友、群和成员来自各自原生服务。

桥接插件提供当前账号的本地服务。wrapper 捕获和会话代理位于 bridge/bootstrap.cjs，原生调用与本地 IPC 位于 bridge/native.cjs，QQ 资源适配位于 bridge/qq-resources.cjs。

Rust app 统一应用状态变化；backend 管理请求关联和连接；store 在专用阻塞任务中访问 SQLite；ui 计算布局与视口；media 在有限并发的工作任务中解码和编码图片；runtime 管理配置和目录；Linux 宿主及显示环境位于 runtime/linux、viewer/linux。platform 提供本地传输、系统打开与安装发现。

## 启动与退出

宿主为 QQ 准备一个保留原始元数据的替代 package.json。进程内 loader 重定向指定文件的只读访问，随后加载本地桥接和 QQ 的原始 main。桥接文件通过原子替换更新，已运行宿主映射的 loader 文件保持原样。

QQ 新版的原生方法有不可写、不可配置的属性。会话代理使用独立对象转发到真实对象，保持 native 调用的真实接收者，等待 QQ 自己初始化完成后取得服务。

Xvfb 禁用 TCP 监听并使用独立 Xauthority。QQ 使用单独的 D-Bus 守护进程，其配置不包含服务自动启动目录；清除桌面会话、Wayland 和激活令牌的继承，运行目录也单独设置。桌面托盘、通知和门户服务不在 QQ 的会话总线上。用户级 systemd 服务管理宿主，QQ、私有 D-Bus 和显示环境依次退出。TUI 与宿主通过用户私有 Unix Socket 通信。

QQ 登录后隐藏原生窗口；临时查看器通过连接租约恢复原有可见状态，连接关闭后再次隐藏。登录、离线及安全验证期间保留原生窗口。

## 同步与恢复

先订阅，再拉初始会话快照。通知使原生状态失效并触发重读。桥接的 epoch 标识原生宿主或账号上下文，切换账号时重新生成；配合事件序号发现连接替换或事件缺口；快照查询开始后发生的事件会促使再次刷新。事件缺口会同时使已加载的历史窗口失效，并重新查询当前阅读位置；进行中的旧查询完成后执行合并后的重读。后续历史查询保持原请求的会话 ID。

原生会话视图的重复订阅可能不再次回调，因此桥接在原生登录完成时注册监听，保留同一宿主内的会话投影并持续接收原生列表变化；没有前端时不传送事件、不更新 TUI 的 SQLite 缓存。

前端按账号和会话保存数据。连接通知和状态响应带本地连接标识；界面工作结果还带账号上下文标识，原生查询同时校验连接及宿主 epoch。账号切回也不会复用旧结果，最后一个连接使用者退出后关闭 socket。成员、资料、联系人、分组和搜索窗口使用独立请求标识。加载窗口可用 Esc 取消；关闭重开或切换账号后，旧结果不再接管窗口。迟到的历史、剪贴板和成员查询响应不会覆盖其他会话；旧历史请求的结果不会替换更新请求。切换账号时清除内存投影，保留按账号隔离的持久化记录。

草稿、引用和附件独立于消息事实。草稿载入完成前暂停正文编辑、粘贴和回复，避免覆盖尚未读取的内容。只有已从数据库加载或经用户编辑的草稿才参与保存，恢复的阅读视图和被动消息事件不能把未加载草稿覆盖为空。发送记录恢复先核对目标会话的持久化草稿，并拒绝覆盖查询期间的新编辑；离线启动也可查看缓存的发送记录。消息视口以消息 ID 和消息内行偏移定位，加载历史及新消息到达时保留阅读位置。启动时按已保存锚点加载附近的缓存窗口；最新原生消息先返回时，保留尚未加载的锚点。连接后按锚点向 QQ 查询连续历史窗口，代替启动时的缓存投影。同一会话只执行一个历史查询，期间的定位或最新页刷新合并为一个后续请求。前后分页沿窗口边缘推进；迟到缓存不再插入窗口之外的消息。阅读旧位置时，窗口之外的新消息只更新提示，按 G 再加载最新页。分页是否结束取决于原生查询结果，旧历史不计入新消息提示。

## 发送

前端先事务性保存发送记录及原草稿，再提交请求。桥接按账号和请求 ID 去重，在调用 native 前保存关联 ID。重复请求携带不同内容时拒绝执行。发送、已读和撤回携带预期原生上下文；上下文变化时拒绝新的修改操作。暂存完成前界面账号上下文失效会取消发送，保留可恢复的原草稿。

原生调用返回成功代表提交成功，最终确认来自消息更新。发送回调可能先于 RPC 响应到达，后续响应不能覆盖已经确认的状态。SQLite 同样拒绝将已确认记录降级为迟到的提交状态。NOSEQ 和超时保留为结果未知。重连查询原生消息核对；不自动重复发送。

## 资源

网络和 SQLite 操作不在绘制函数中等待。每轮绘制前分别处理最多 64 条后台操作结果和原生事件；操作结果逐条应用，同一通知内的消息按会话批量合并。宿主状态查询同时只保留一个进行中的请求。图片只为可见区域调度，解码限制尺寸和分配量，最多两个图像工作任务并行。缓存同时受数量和估算字节数约束；退出、缩放和缓存清理处理终端图像资源。

媒体和外链只通过选定消息解析；系统程序通过参数数组启动。控制字符在呈现前过滤，保留中文、换行和普通正文。

标记已读仅在终端有焦点、原生历史加载完成、已到最新消息且底部视口未被遮挡时提交。成功响应后保存本次已读位置；失败后间隔两秒重试，同一会话同时只保留一个请求，宿主变化或过期回调不会覆盖新请求状态。

进入群聊时先捕获原生最早未读消息的位置，捕获完成前暂缓自动已读。该位置独立于未读计数，在当前会话中保留；跳转复用历史定位与阅读返回栈。

## 引用与图片查看

引用内容独立于当前连续历史窗口缓存。仅为可见引用发起读取；同时最多八个任务，每会话最多缓存 256 个引用状态。结果校验账号、会话、连接、宿主 epoch 和请求代次，过期结果不接管新的选择。引用记录持久化到 SQLite，撤回会更新引用内容并使旧读取失效。跳转使用原生 around 查询，返回栈保存原阅读锚点、行偏移及消息选择。

图片查看器使用独立于行内预览的缓存键。图片保持宽高比，以实际渲染尺寸在弹窗内容区居中，生成图像限制为四百万像素。

会话列表的光标与当前打开的会话分别按原生会话 ID 保存，原生重排不会把光标带到其他会话。绘制时记录可见行与面板的命中区域，鼠标点击和滚轮复用键盘导航的历史边界判断；弹窗期间阻止操作穿透。最新窗口到达实际底部后恢复跟随，已读仍受终端焦点和加载状态约束。

GIF、APNG 和 WebP 根据文件内容识别动画，使用解码器合成后的帧和原始延迟循环播放，最多每秒刷新 20 次。仅为可见动画调度帧编码，共用两个后台工作槽；Kitty 动图沿用同一图片 ID，通过帧更新指令替换像素，不触发文字重绘或移动光标；缓存、在途和待回收 ID 统一管理。单个动画最多 512 帧，解码帧缩略图按行内 8 MiB、查看器 24 MiB 的预算逐步缩小，全部图像缓存仍限制为 64 MiB。终端缩放使旧编码任务失效，迟到结果不会恢复已清理的图像。

消息正文保留文字与附件引用的有序 parts。文字和表情共享行内排版，表情占用固定单元格并提升所在行的高度；仅在行宽不足时折行。复制、搜索和引用摘要继续使用规范化的纯文本后备。合并转发的 XML 使用受限长度的 XML 解析器读取标题和摘要，通过原生 getMultiMsg 展开，异步结果校验账号、宿主与弹窗请求代次，内容不合并进当前会话窗口。

商城表情沿用锁定 NapCat 上游的 QQ CDN 路径，以原生 emojiId 构造资源地址；地址不能由消息任意指定。资源下载最多八个同时进行，同 ID 合并请求，单文件上限 16 MiB、超时 15 秒，临时文件原子替换后供普通图像流程读取。

表情回应采用原生 emojiLikesList、setMsgEmojiLikes 和分页成员查询。只有回应的更新不会替换正文，XML 回应通知触发目标消息的原生重读。QQ 收藏和基础表情通过选择器加入草稿，仍使用原有发送暂存与恢复流程。

媒体请求最多八个同时进行，重复请求合并，错误保留并由用户显式重试；宿主变更取消原生等待者。

转发记录的消息带有 forward_path，标识从会话根卡片到当前记录的层级。资源查询重新验证该路径，以原生返回的消息与元素定位下载；请求与结果均保留账号、会话、记录路径和元素标识。它们只更新当前弹窗或它的返回视图，不写入普通时间线。正文和转发记录共用富文本排版、解码预算及 Kitty 图像生命周期。

打开对象时从有序消息元素提取附件和 HTTP/HTTPS 链接，单项直接打开，多项交给紧凑选择器。链接边界使用 linkify，输入词边界使用 unicode-segmentation。原生灰条使用结构化 system_notice／reaction_notice 标记，回应提示的原生序号复用定位与返回栈。

转发图片优先使用 QQ 原生返回的完整 originImageUrl，保留原有鉴权参数；只有相对引用或完整地址失效时，使用原生 MD5 对应的 QQ 标准 gchatpic_new CDN 访问格式。图片缓存最多 64 项、128 MiB，已有原图继续使用 QQ 原目录。下载复用 QQ 资源适配器的 HTTPS 域名校验、重定向限制、单文件 16 MiB、最多八个在途请求、超时和图片内容校验；已有 QQ 本地原图优先。文件／视频使用原生 visit 下载接口。

## 邮箱、显式已读与通知

QQ 邮箱的原生 103 会话共用消息时间线和历史分页，发送在前端与桥接两端禁用。会话菜单持有打开时的原生会话 ID，和消息动作菜单分别处理；显式已读不要求打开聊天或滚到底部，但仍验证账号及 epoch，随后重新读取原生状态。

桌面通知由 TUI 的有界工作队列调用 notify-rust。notifiedType=2 的在线非本人新消息生成提醒，按会话／消息 ID 去重；免打扰群中的重要 @ 提醒使用相同判定。窗口标题使用原生主列表提醒计数，通知正文转义桌面标记。

媒体失败缓存只保存有界的错误状态，显式重试或原生上下文变化才清除；失败不会自动退出预览。原生下载与 QQ 资源地址均失败后，若本地缩略图存在，则返回路径及 warning，查看器持续显示降级原因，缩略图不标作原图。

## 请求作用域和资源所有权

查询结果携带 RequestContext（账号、本地视图代次、连接及原生 epoch），在统一入口接受或拒绝。只依赖本地数据的结果使用视图作用域，连接恢复不使本地草稿读取失效；成功发送回执属于持久事实，按账号及请求 ID 合并，不因旧连接而丢弃。历史分页、草稿版本和弹窗／头像 token 保留各自业务代次。

账号变化先把旧账号的脏草稿排入 SQLite 事务并等待成功，再集中清除消息、头像、弹窗、请求和终端图形上下文。保存失败保持旧本地视图以便重试。自动保存同步登记到有界数据库队列，只有版本匹配的成功回报才能清除脏态；退出、发送暂存和账号保存使用同一 FIFO，不由后台任务的启动先后推断落盘顺序。

发送日志由 journal worker 独占一个 SQLite 连接，主线程只发送有界命令。数据库索引负责冷回执与原生关联 ID 查询，内存热回执限制为 256 条；确认记录不能被迟到状态降级。原生提交必须在日志确认及再次验证上下文之后执行。

文本排版按消息本地版本、宽度及媒体几何缓存，不在动画每帧重建全部正文。每会话窗口最多 600 条，最多 8 个活跃窗口，总消息预算 32 MiB；草稿独立保留。图片编码缓存 64 MiB、128 项，两个工作槽、八个排队项；预算不足时稳定暂缓准入，避免整批清空后重复编码。

CacheLease 保护正在编辑、发送或缓存显示的本机托管文件；磁盘清理同时读取持久草稿／未决发送引用并尝试独占文件租约。目录清理在独立阻塞任务中执行，不占用数据库工作线程；清理范围仅限 qqtui 管理的缓存，不删除 QQ 原目录资源。

宿主用具名子进程管理 QQ、Xvfb 和 D-Bus。初始化失败和运行期退出均进入统一关停，显示清理核对 PID 及 socket 身份；不清理其他显示服务器。桥接资源整组按内容摘要落入不可变目录，已有运行实例不受新版本物化影响。

## QQ 兼容性

bridge/compatibility.json 记录平台、架构、版本和 wrapper 指纹。启动时检查版本，加载时检查模块指纹。支持新版本时，更新兼容配置并验证原生接口及资源布局。

SDK 的接口名、消息类型、参数结构和资源路径集中在桥接适配层；接口契约见 [桥接协议](PROTOCOL.md)。

## 平台支持

完整宿主和发行包面向 Arch Linux x86_64。Windows 前端的适配涵盖命名管道、用户目录、安装发现、剪贴板和系统打开。

QQ 安装发现使用 PATH、桌面登记和包管理器信息；`setup --qq-path` 可指定安装位置。

多账号目录适配位于 bridge/accounts.cjs。进程元数据和登录状态按实例保存，聊天数据通过原生 account_path 指向 QQ 数据目录。新增平台时需核对 SDK 的全局目录和账号目录语义。

## 存储依赖

Linux 使用系统 SQLite，最低版本为 3.51.2；该版本修复了并发 WAL 访问的 [Unix VFS 锁问题](https://sqlite.org/releaselog/3_51_2.html)。Windows 使用 bundled SQLite。
